# TDD 스킬

이 스킬은 Python `unittest`를 사용해 테스트 주도 개발(TDD)의 Red-Green-Refactor 사이클을 실제로 수행하기 위한 절차를 정의한다. 이 스킬은 구현할 "무엇"(품질 기준, 산출물 템플릿 등)을 다루지 않는다 — 그것은 `implementation` 스킬의 범위이며, 이 스킬은 "어떻게 순서대로 작업하는가"만 다룬다.

## 1. 원칙

- **테스트 없는 구현 코드를 작성하지 않는다.** 대응하는 실패한 테스트가 먼저 존재하지 않는 프로덕션 코드는 작성하지 않는다.
- 각 단계(Red/Green/Refactor)마다 테스트를 실제로 실행해 결과를 확인한다. 실행하지 않고 "통과할 것"이라고 가정하지 않는다.
- 한 번에 하나의 동작/검증기준만 다룬다. 여러 기능을 한 번에 구현하지 않는다.

## 2. 입력

- 구현 대상 유닛(가능하면 `detailed-design` 스킬 산출물의 `DES-UNIT-*`)과 그 유닛 검증기준(입력/기대출력/경계조건) 목록.
- 입력이 없으면 사용자에게 요청하거나, 저장소의 상세설계 산출물을 탐색한다.

## 3. Red-Green-Refactor 절차

대상 유닛의 검증기준 목록 중 아직 다루지 않은 항목이 있는 한 다음을 반복한다.

1. **RED**: 다음에 다룰 검증기준 하나를 선택한다. `unittest.TestCase`를 상속한 테스트 클래스에 그 동작을 검증하는 테스트 메서드(`test_`로 시작)를 작성한다. 아직 구현이 없거나 해당 동작을 지원하지 않으므로 테스트를 실행해 **실패하는 것을 실제로 확인**한다.
2. **GREEN**: 그 테스트를 통과시키는 데 필요한 가장 단순한 구현만 작성한다(다른 검증기준을 미리 구현하지 않는다). 테스트를 다시 실행해 통과를 확인한다. 이 시점에서는 코드 품질 지표(라인수/복잡도 등)를 아직 만족하지 않아도 된다.
3. **REFACTOR**: 테스트가 계속 통과하는 상태를 유지하면서 코드를 정리한다(이름 개선, 중복 제거, 구조 개선). `implementation` 스킬의 코드 품질 지표를 이 단계에서 적용한다. 리팩터링을 마칠 때마다 테스트를 다시 실행해 여전히 통과하는지 확인한다.
4. 다음 검증기준으로 돌아가 1~3을 반복한다. 모든 검증기준을 커버할 때까지 계속한다.

## 4. 테스트 작성 규칙

- 테스트 클래스는 `unittest.TestCase`를 상속한다.
- 테스트 메서드명은 `test_`로 시작하고, 검증하는 시나리오를 알 수 있게 짓는다.
- 각 테스트에는 어떤 요구사항/유닛 검증기준을 다루는지 docstring이나 주석으로 ID를 명시한다(추적성 확보 — 예: `# covers: DES-UNIT-003 / REQ-SW-F012`).
- 정상 케이스뿐 아니라 유닛 검증기준에 명시된 경계값·예외 케이스도 각각 별도의 테스트로 다룬다.

## 5. 회귀 테스트 규칙

- 버그를 수정할 때도 먼저 그 버그를 재현하는 실패 테스트를 작성한 뒤(RED), 수정하고(GREEN), 정리한다(REFACTOR). 테스트 없이 바로 수정 코드를 작성하지 않는다.

## 6. 실행 환경

- 이 스킬은 테스트를 실제로 실행할 수 있는 환경(예: `python -m unittest`)을 전제로 한다. 실행할 수 없는 환경이면 그 사실을 사용자에게 알리고, Red/Green 여부를 추정하지 않는다.

## 7. 보고

각 사이클이 끝나면 다음을 보고한다: 이번에 다룬 검증기준, 작성한 테스트, Red 확인 여부, Green 확인 여부, 리팩터링 내용, 남은 검증기준 목록.
