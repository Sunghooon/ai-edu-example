# SW 시스템 테스트 케이스 생성

## 개요

SW 요구사항 명세서 기반으로 SW 시스템 테스트 케이스를 생성하기 위한 방법론 스킬입니다. 이 스킬은 "무엇을 근거로, 어떤 기법으로, 어떤 원칙으로" 테스트 케이스를 설계할지에 대한 방법론만 정의합니다. 요구사항 분석, 사용자와의 확인, 실제 산출물(xlsx) 작성은 이 스킬을 사용하는 에이전트(예: `sw-system-tester` 서브에이전트)가 수행합니다.

## 적용 범위 (다른 스킬과의 경계)

- 이 스킬은 A-SPICE **SWE.6(소프트웨어 검증시험/자격시험)** 수준, 즉 **SW 요구사항 명세서 전체**를 베이시스로 한 시스템 테스트 케이스 설계를 담당한다. 아래 "기반지식"에 A-SPICE SWE.4/SWE.5를 함께 적는 것은 양방향 추적성·표준화된 시험 절차라는 공통 개념을 공유하기 때문일 뿐, 이 스킬이 유닛/통합 수준 테스트 케이스를 직접 만든다는 뜻은 아니다.
  - 유닛(SWE.4) 수준 테스트 코드는 `tdd`(+ `implementation`) 스킬이 담당한다.
  - 통합(SWE.5) 수준, 아키텍처 인터페이스 기반 테스트는 `software-integration-testing` 스킬이 담당한다.
- 이 스킬이 정의하는 블랙박스 테스트 설계 기법 카탈로그("적용 대상 테스트 기법")는 이 프로젝트에서 테스트 레벨과 무관하게 통용되는 공통 정의다. `tdd`, `software-integration-testing`에서 동일 기법명을 사용할 때도 이 카탈로그의 정의를 따르며, 각 스킬에서 별도로 재정의하지 않는다.
- 비기능 품질특성 분류는 `requirements-analysis` 스킬이 요구사항 작성 시 사용하는 **ISO/IEC 25010**(ISO 25000 SQuaRE 시리즈의 제품 품질모델) 8개 특성을 그대로 이어받는다 — 새로운 분류 체계를 만들지 않는다.

## 기반지식

- **ISO 26262 Part 6**: 소프트웨어 단위/통합/시스템 테스트에 대한 요건. 특히 ASIL 등급이 할당된 요구사항은 판정기준의 전 분기(경계값, 조건 조합)를 빠짐없이 검증해야 합니다.
- **A-SPICE SWE.4, SWE.5, SWE.6**: 소프트웨어 단위 검증, 통합 시험, 시스템 시험에 대한 Base Practice. 양방향 추적성(요구사항 ↔ 테스트 케이스)과 표준화된 시험 절차를 요구합니다. 이 스킬이 실제로 산출물을 생성하는 범위는 SWE.6이며, SWE.4/SWE.5는 배경 지식(위 "적용 범위" 참고)입니다.
- **ISO 29119 및 ISTQB**: 테스트 시나리오·테스트 케이스 설계 프로세스와 용어 체계(긍정/부정 분류 등)의 근거로 사용합니다.
- **ISO/IEC 25010 (ISO 25000 SQuaRE 시리즈의 제품 품질모델)**: 비기능(품질) 요구사항을 분류하는 기준입니다. 비기능 테스트 케이스는 이 표준의 품질 특성(기능적합성, 성능효율성, 호환성, 사용성, 신뢰성, 보안성, 유지보수성, 이식성)별로 그룹화합니다.

## 템플릿 우선순위 (필수 선행 절차)

1. 사용자가 이번 대화에서 직접 제시한 산출물 양식이 있으면 그것을 그대로 따릅니다.
2. 저장소의 표준 산출물 템플릿(`WP_Templates/`)을 사용합니다. 세부 위치·형식별 처리 방법·라이선스 주의사항은 `references/templates.md`를 반드시 먼저 읽고 따릅니다. 핵심 템플릿:
   - SW 검증 명세서: `WP_Templates/Engineering/SoftwareVerification/TPL-SWE6-001_SW 검증 명세서 템플릿.xlsx`
   - SW 검증 결과서: `WP_Templates/Engineering/SoftwareVerification/TPL-SWE6-002_SW 검증 결과서 템플릿.xlsx`
   - 양방향 추적 매트릭스: `WP_Templates/Engineering/Traceability/TPL-TRC-001_양방향 요구사항 추적 매트릭스 템플릿.xlsx`
   - 전체 템플릿 목록과 적용 산출물 매핑은 `WP_Templates/PRC-TPL-001_표준 산출물 양식 등록부.xlsx`를 따릅니다.
3. 위 템플릿 파일을 저장소에서 찾을 수 없는 경우에만 "산출물 구조"에 설명된 최소 구조(시트 구분)를 사용하고, 산출물 상단에 "표준 템플릿을 찾지 못해 최소 구조를 사용함"이라고 명시합니다.

## ID 체계 및 추적성

- 시스템 테스트 케이스 ID: `STC-nnn`. 각 케이스에는 대상 요구사항 ID(`REQ-SW-F*`/`REQ-SW-N*`, `requirements-analysis` 스킬의 체계)를 함께 기재해 양방향 추적성을 확보합니다.
- 이 스킬을 사용해 테스트 케이스를 신규 작성/변경할 때마다 `docs/traceability/traceability-matrix.md`에 `STC-*` 열을 추가/갱신해, 요구사항 ↔ (아키텍처 ↔ 상세설계 ↔ 코드/유닛테스트 ↔ 통합시험) ↔ 시스템 테스트까지 이어지는 사슬을 완성합니다. 이 매트릭스 갱신은 이 스킬을 사용하는 에이전트가 수행합니다.
- 모든 SW 요구사항(`REQ-SW-*`)이 하나 이상의 `STC-*`로 커버되는지 점검하고, 누락된 요구사항을 보고합니다.

## 적용 대상 테스트 기법

요구사항의 성격에 맞춰 아래 기법 중에서 선택하여 적용하고, 각 테스트 케이스의 "사용 기법" 항목에 실제로 적용한 기법을 명시합니다.

- **경계값 분석**: 검증기준에 수치·범위·임계값이 있는 경우, 경계값 미만/경계값/경계값 초과를 각각 별도 케이스로 도출합니다.
- **동치 클래스(동등분할)**: 입력 도메인을 유효/무효 클래스로 나누어 대표값을 도출합니다.
- **조합 테스트(전 조건 조합)**: 관련 조건 수가 적어 전수 조합이 실행 가능한 범위일 때 우선 적용합니다.
- **페어와이즈**: 조건·값의 조합 수가 많아 전수 조합 테스트가 비현실적인 경우에 대체 적용합니다.
- **엣지 케이스**: 정상 범위의 극단, 동시성/타이밍 등 일반 분석 기법으로 포착되지 않는 특이 조건을 다룹니다.
- **경험 기반 테스트**: 유사 시스템의 결함 이력이나 QA 경험에 근거해 오류를 추정합니다(오류 추정, 탐색적 테스트 등).

## 작성 원칙

- **테스트 성공률 100%**를 달성합니다(CLAUDE.md 시스템 테스트 지침). 실패한 테스트 케이스가 있으면 원인을 해결하기 전까지 완료로 보고하지 않습니다.
- 의미 없이 테스트 커버리지 수치 달성만을 목적으로 하는 케이스는 생성하지 않습니다.
- 테스트의 예상 결과를 임의로 가정하지 않습니다. 명세서에 근거가 없다면 이 스킬을 사용하는 에이전트가 사용자에게 확인을 받아야 합니다.
- 프로젝트에서 정한 테스트 커버리지 목표(예: CLAUDE.md에 명시된 기준)를 준수합니다.
- 실행자가 그대로 재현할 수 있는, 실행 가능한 테스트 케이스만 작성합니다.
- 기법 선택이나 커버리지 범위 설정이 판단하기 어려운 경우 임의로 결정하지 말고, 이 스킬을 사용하는 에이전트를 통해 사용자 검토를 받습니다.
- 명세서에 직접적 근거는 없으나 QA 관점에서 추가를 제안하고 싶은 테스트 케이스는 테스트 케이스명 끝에 "(제안)"이라고 표시해 구분합니다.
- 사용한 테스트 설계 기법을 각 케이스에 명시합니다.

## 도구 사용

- 페어와이즈 조합을 생성할 때는 오픈소스인 PICT를 사용합니다.
- 전수 조합(모든 조건의 조합)을 생성할 때는 PICT의 `/o:max` 옵션을 사용합니다.

## 산출물 구조

- 기능 요구사항에 대한 테스트 케이스: "테스트 케이스" 시트(또는 TPL-SWE6-001/002가 정의한 동일 목적 시트)
- 비기능 요구사항에 대한 테스트 케이스: 별도의 "비기능 테스트 케이스" 시트, ISO/IEC 25010 품질 특성별로 구분
- 각 테스트 케이스에는 `STC-nnn` ID와 대상 요구사항 ID를 기재해 추적성을 확보(위 "ID 체계 및 추적성" 참고)
- 요구사항 원문에 없거나 원문보다 엄격하게 사용자 확인을 거쳐 확정한 판정기준: "확정 근거" 열에 확정 일자와 승인 주체 기록

## 산출물 배치 규칙

- 테스트 케이스/결과 문서: `references/templates.md`에 명시된 템플릿 경로(TPL-SWE6-001/002)를 복사해 사용
- 추적성 매트릭스: `docs/traceability/traceability-matrix.md` (기존 파일에 이어서 갱신)

저장소에 기존 문서 구조가 있으면 그것을 우선합니다.
